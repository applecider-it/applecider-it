## ハイブリッドMPA

- JSフレームワークは、メンテナンスしやすいVueを選択。

- CSS管理は、いろいろと便利なTailwindを選択。
  
  - 管理を楽にするため、基本パーツだけは@applyでまとめています。

- フレームワークは、無難なRails,Laravelを選択。

- JS管理は、管理しやすいTypeScriptを選択。

- JSビルドはViteのため、開発環境、本番環境どちらも快適に動きます。

- これで、SPAと、ぱっと見、違いがわからないくらいの実装は可能でした。

- ハイブリッドMPAを取り入れている具体例は、Amazonなど。

## ハイブリッドMPAのメリット

- 基本はMPAなので、エンジニアの確保が簡単。

- コストがかからない。

- 枯れた技術なので、セキュリティ面も比較的安全。

- ページ遷移で最新版になるので、サーバーサイドのバージョン管理が不要。

- SEOで有利。

- それなのに、インタラクティブな機能も実装可能。

- インタラクティブな機能も、JSが比較的簡素になる。

- Viteのビルドは、最適化されるため、初期ロードが早くなります。

## アプリ化の要望があった時にも得したい場合

- PWAで済ませられる場合は、jsonを用意すればアプリ化が終わります。

- あとは、インストール方法を説明するページだけ用意すればいいと思います。

- これだと、審査不要、サーバーサイドのバージョン管理不要、手数料もかかりません。

- モバイルアプリだけじゃなくてPCアプリにもなります。

- 実は、スペック的には、Capacitor、Electronでアプリを作るのに近い状態です。

## 他にも、安く済ませたい場合

- WebSocketサーバーは、チャットのみにして、遅いジョブの状態管理はポーリング。

- Push通知は、管理コストが高いので、メール、Slackへの送信にして、ユーザーには、そちらの通知を有効にするように伝える。
